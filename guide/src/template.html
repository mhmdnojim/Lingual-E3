    From a dead Flash app to a modern browser app

    This guide explains how the old American English File 2e Level 3 classroom software was rebuilt to run in a web browser. It shows every step, every feature, the real code (read directly from the project files), every screenshot, and small live demos you can try here.

    1. Overview

    What the old app was

    The disc contained Oxford iTools 2.0 (2014). It was a desktop program (windows/oup.exe) built on Mozilla XULRunner (an old Firefox engine). It showed book pages with a map library called OpenLayers and played audio, video and answer keys with Adobe Flash Player 13.

    Adobe stopped Flash at the end of 2020, and XULRunner is no longer maintained. The program also checked a licence online. So on a modern Windows 11 computer the app no longer worked.

    What the new app does

    The new version is a small website that runs only on your own computer. A tiny Python server sends the files to Microsoft Edge or Chrome. No Flash and no internet are needed (except for the optional “Natural” voices).

    The content was converted once by build scripts. The page images, audio and answer keys come from the original disc. The page text was read from the page images with OCR, and it is what makes every sentence, clause and word clickable.

    Why
    • Heavy work happens once. Joining tiles and OCR take about 20 minutes, so they are not done in the browser.
    • No frameworks. The app is plain JavaScript modules, so there is nothing to install or compile, and it will keep working for many years.
    • Original files are reused where browsers can play them (MP3, page tiles, SWF through Ruffle). Only the videos had to be converted.
    • The original app is not changed. All new files are in web\ and guide\.

    5. The build pipeline

    All build scripts are in web\tools. Shared paths and the page geometry are in common.py:

    Run everything

    build_all.ps1 runs all steps in order. Every step skips work that is already done, so it is safe to run again.

    Step 1 — Join the tiles into page images

    Goal: one image per page, because one image is simpler to show and is needed for OCR.

    How: for each of the 16×16 tiles at zoom 4, paste it at x = column × 124, y = (15 − row) × 156. The 15 − row part flips the bottom-based rows.

    Try itTile layout
    Point at a tile.

    The bug the pilot found: some tiles are transparent (black text on no background). Converting them straight to RGB made the transparent parts black. The fix is to paste each tile with its alpha mask onto a white page.

    Each page is then saved three ways: a WebP for the app (quality 88, about 270 KB), a 240 px thumbnail for the page grid, and a lossless PNG only for OCR (deleted afterwards).

    Step 2 — Read the text (OCR)

    Goal: know every word on the page and where it is (a box in pixels). The boxes are what make the text clickable on top of the image.

    Tool: the OCR engine built into Windows 10/11 (Windows.Media.Ocr). It is free, offline, already installed, fast (about 1 s per page) and very accurate on printed text. It returns lines, and each word with its bounding box.

    How: Windows OCR is a “WinRT” API. Windows PowerShell 5.1 can call it, but its functions are asynchronous. The trick is to turn each WinRT operation into a .NET Task with AsTask and wait for it:

    Then for each page image: open the file, decode it to a bitmap, and recognise it with the English engine:

    Step 3 — Sentences and clauses

    Goal: OCR only gives lines and words. To click a sentence or a clause, the words must be grouped. This is done in four stages in segment_text.py.

    a) Clean the words

    Remove noise: the audio icon is read as @9))) or @10)), and lone symbols have no letters. Fix a common slip: 0K → OK.

    b) Group lines into blocks

    Two lines belong to the same block (paragraph) only if all these are true: similar font size, the gap between them is small, they overlap horizontally, the new line is not further left (a new column), the first line is not a short heading above longer text, and the new line does not start a numbered item.

    Tuning

    The rules were tuned on real pages. Examples: a one-word last line (“context.”) has a smaller box, so the font-size rule only compares lines with 3+ words; the removed audio icon is still used for the line's left edge, so the line is not seen as indented.

    c) Split blocks into sentences

    A word ends a sentence if it ends with . ! ? …, it is not an abbreviation (Mr., e.g., p. …) or an initial, and the next word starts with a capital letter, a digit or a quote.

    d) Split sentences into clauses

    A clause ends after , ; : or a dash. A new clause also starts before a linking word: because, although, when, if, which, who… (both sides at least 2 words), or and, but, or, so (both sides at least 4 words, so “Rutledge and Adam” is not split). One-word pieces like “However,” join the next clause.

    Try itSentence and clause splitting (same rules, in JavaScript)

    Point at the text to see the unit; click it to hear it. Yellow/blue = sentences, red underline = clauses.

      e) Save the result

      Each page becomes a compact JSON file. Words are arrays (smaller than objects); sentences, clauses and blocks are ranges. The same script also writes one search file per book.

      Step 4 — Convert the videos

      The 38 FLV videos use VP6, which no browser can play. convert_videos.py uses ffmpeg (from the imageio-ffmpeg Python package, so nothing else has to be installed) to make MP4 files with H.264 video and AAC audio. +faststart puts the index at the start of the file so playback starts at once.

      Result: 38 MP4 files, 332 MB (the FLVs were 625 MB), none failed.

      Step 5 — Book index, hotspots and transcripts

      build_data.py writes web\data\books.json: every book, every page in order, and every hotspot with its position in image pixels.

      Converting positions

      The old map units count y from the bottom. The image counts y from the top. So: x = lon and y = 2496 − lat.

      Try itHotspot position converter (Student Book p.25)

      Click a coloured dot (the real hotspots of this page) or anywhere on the page, or type values.

      Transcripts

      Each audio/video XML script is turned into a short JSON list of {t: milliseconds, x: text}. HTML tags inside the old CDATA text are removed, and the line_return markers are skipped.

      Blank pages

      156 of the 226 Teacher's Book pages are not on the disc: their 256 tiles are plain white (about 270 bytes each). They are marked "blank": true so the app can say so.

      Each feature shows what it does, a screenshot, how it works, and the code. Click Open full file on any code block to see the whole file.

      6.1 The local server

      Why it is needed: browsers do not let a page opened from file:// load JSON files, Ruffle needs to load .wasm files with the right type, and audio/video seeking needs “Range requests” (asking for only part of a file). Python's built-in server does not support Range, so server.py adds it.

      • Listens on 127.0.0.1 only — other computers cannot connect.
      • Serves the main folder, so /web/… (the app) and /.shared/… (original audio and answer keys) both work.
      • Tries ports 8765–8784 if one is busy, then opens the browser.

      The server also stores text corrections, My audio MP3s and translations through a small JSON API (only for this app: changes from other web sites are refused by checking the Origin header):

      RequestWhat it does
      GET /api/text/<book>/<page>The corrected page text if there is one (with "edited": true), else the OCR text
      PUT /api/text/<book>/<page>Checks and saves corrections to web\edits\<book>\<page>.json
      DELETE /api/text/<book>/<page>Removes the corrections (back to the OCR text)
      GET /api/search/<book>The book's search file with corrected pages applied
      GET /api/voices, /api/voice-sampleThe Natural voices for My audio, and a short sample of one
      POST /api/recordings, GET /api/jobs/<id>Starts making an MP3, then reports its progress
      GET /api/recordings, PUT / DELETE /api/recordings/<id>Lists, renames and deletes My audio MP3s
      GET /api/tr-languagesThe 43 translation languages
      POST /api/translate, /api/translate-wordTranslations of a page's sentences (saved in web\translations), and of one word
      GET /api/version, POST /api/quitLets the page notice an older server, and lets a new start of the app replace an old one

      6.2 The page view

      Each page is a stack of four layers in one box with the page's aspect ratio (1984 : 2496):

      1. Image — the stitched WebP page.
      2. SVG text layer with viewBox="0 0 1984 2496". Because the SVG uses the same pixel units as the OCR boxes, the boxes line up at any zoom with no maths.
      3. Inside the SVG: highlight groups (hl-active, hl-word, hl-flash, hl-hover) and on top the invisible click targets (hits, one rectangle per word).
      4. Hotspot buttons, placed with percentages (left: x/1984, top: y/2496) and centred like the original icons.

      Highlights use mix-blend-mode: multiply, so they look like a real highlighter pen on paper:

      6.3 Clickable text: sentence, clause, word

      How it works:

      1. When a page loads, its text JSON becomes a PageText object. It builds two lookup tables: word → sentence and word → clause.
      2. Each word gets an invisible rectangle, widened to meet its neighbours, so there are no dead gaps between words.
      3. When the pointer moves over a rectangle, the app asks unitAt(word, mode) for the sentence/clause/word around it, and draws one rounded rectangle per text line of that unit.
      4. A click sends the unit to the reader (6.5): it reads from there to the end of the page; clicking the same unit again pauses or continues.

      The mode buttons set a class on <body>; with mode “Off” the click targets ignore the pointer, so the page behaves like a plain picture:

      6.4 Text to speech (the “voice”)

      The app uses the browser's Web Speech API (speechSynthesis). Nothing is installed: Edge and Chrome use the Windows voices (David, Zira, Mark — offline), and Edge adds high-quality online Natural voices.

      • Choosing a voice: English voices are ranked: “Natural” first, then US, then UK.
      • Ignoring old events: every speak() increases a counter, so events from a cancelled sentence are ignored.
      • Offline fallback: if an online voice fails (no internet), the same text is spoken again with an offline voice.
      • Word highlighting: the browser fires a boundary event with a character position for each word. The app remembers where each word starts in the spoken text, so it can find the word and highlight it.
      • Clean speech text: bullets are removed, p.104 becomes “page 104”, dashes become pauses, and exercise numbers glued to words (2was) are removed.
      Try itSpeak with word highlighting (works in Edge and Chrome)

      6.5 Read aloud: click, pause, continue

      You doWhat happens
      Click a sentence (or clause)If one of your My audio MP3s contains it, that MP3 plays from there. Otherwise reading starts there with the live voice and goes on to the end of the page (both pages in two-page view).
      Click the sentence being readPause. Click it again: it continues from the word where it stopped.
      Click another sentenceReading starts again from that sentence.
      Word mode: click a wordOnly that word is read.
      Space, or Pause/Continue in the barPause / continue. Esc or Stop ends reading.
      Voice settings → Pause between sentencesAfter each sentence (or clause) the app waits the chosen time — none up to 10 s — before reading the next one: time to repeat it aloud. The bar counts down (“Next sentence in 3 s”).

      How it works: the Reader has a state (idle, playing, paused) and a queue of units from the clicked one to the end of the visible pages. When one unit ends, the next starts.

      • Pause stops the speech engine but remembers the last word reported by the boundary event. Continue speaks the same unit again from that word. This works with every voice, even ones where the browser's own speechSynthesis.pause() is unreliable.
      • Smooth flow: every request to a voice takes a moment to start (the online Natural voices wait for Microsoft's server), so reading sentence by sentence left a gap after each one. speakFrom therefore gives the voice up to 10 sentences (1,500 characters) of the page in one request. The voice reports the position of each word; from it the app knows which sentence is being read and moves the highlight. One sentence at a time is used only when a pause between sentences is chosen, in word mode, and for voices that report no word positions.
      • Pause between sentences: when a unit ends, finished() waits settings.gap seconds before the next one (tickWait() updates the countdown). The finished sentence stays highlighted. Pausing during the wait and continuing goes straight on to the next sentence.
      • Each new sentence is centred in the Text list (centerPanel) and kept visible on the page (reveal). A click on the page also switches the side panel to the Text tab.

      Repeat each sentence

      The Voice tab has Repeat each sentence: once (normal), 2 to 10 times, or ∞ (the slider's last step) — the same sentence again and again until you click another one, pause or stop. The reader keeps a counter (round): when a sentence ends, finished() reads it again until the count is reached, then goes on; the pause between sentences is also made between the repeats, and the bar shows “2nd time of 3” or “6th time, ∞”. Repeats are read one sentence per request (not in the 10-sentence pieces). With a My audio MP3 the same setting works by jumping back: when the MP3 reaches the next sentence by itself, it goes back to the start of the one being repeated (follow; the last sentence on the ended event); in Word mode the word is played again after a short silence.

      Quicker than the slider: the repeat button in the top bar, next to the translate button (or R). Each click goes 2 → 3 → 4 → 5 → ∞ → once; a small badge on the button shows the number (none for once). It changes the same setting as the slider, so both always agree (cycleRepeat, showRepeat).

      6.6 Text extraction: the Text panel

      The side panel shows the page text by paragraph, with every sentence numbered and on a line of its own (<span class="sline"> with display: block); a translation goes under its sentence. Each word is a <span> with its trailing space, so highlights have no gaps. Pointing and clicking in the panel works exactly like on the page, and both stay in sync (markPanel). You can also select text with the mouse to copy part of it.

      • Translation button (next to the pencil): shows or hides the translations in the list (same as L); the one at the top does the same for the popup on the page.
      • Numbers: each sentence has its number on the left (the same numbers as in correction mode); when the pointer is over a sentence its number turns into the dots to drag it.
      • Drag a sentence by the dots that appear on its left to move it, and double-click a sentence to correct it right there — no need to open correction mode (see 6.17).
      • A single click waits 0.28 s before reading, so that a double click is not also taken as “read”.
      • Copy uses the Clipboard API, with an old execCommand('copy') fallback.
      • Save .txt makes a file in the browser with a Blob (Windows line endings).
      • Save the whole book reuses the search file, which already has every page's text.

      6.7 Audio with a script that follows

      Clicking a headphones button plays the original MP3 (straight from .shared) in an HTML5 <audio> element. On every timeupdate event, the transcript finds the last line whose start time has passed and highlights it. Clicking a line sets currentTime, which works because the server supports Range requests.

        6.17 Text corrections

        OCR is never perfect, so the text can be corrected inside the app. The corrections are used everywhere: reading aloud, clicking on the page, copying, saving and search.

        Quick corrections in the Text list

        The two most common fixes need no special mode: double-click a sentence to change its text, drag it by its dots to move it. Ctrl+Z undoes them. They use the same corrections (OPS.text, OPS.moveTo), undo history and saving as correction mode; afterwards the list is drawn again and the sentence stays highlighted in the middle (textChanged).

        Correction mode: all the tools

        Button (bar at the top)What it does to the selected sentence
        Pencil · Enter · double clickChange the sentence text — fix a word, a capital letter, punctuation… (Enter saves, Esc cancels)
        SplitShows the words as buttons; click the word that starts the new sentence.
        Merge ↑ / Merge ↓Join with the sentence before / after. If that sentence is in another paragraph, the two paragraphs are joined (for a sentence that OCR cut in the middle).
        Drag and dropDrag a sentence by the dots on its left; a blue line shows where it will go — between two sentences, at the end of a paragraph or the start of the next. The list scrolls by itself near its edges.
        Move up / Move downSwap places with the sentence before / after, also across paragraphs.
        New paragraph / Join paragraphStart a new paragraph with this sentence, or (for the first sentence of a paragraph) join it to the paragraph above.
        Add after / + Add at the endType a missing sentence. It has no place on the page yet (“not on page”).
        Mark on pageDrag a box around the sentence on the page image; its words are laid out inside the box so it can be clicked and highlighted there.
        DeleteRemove the sentence.
        Undo · RestoreUndo the last change (Ctrl+Z, up to 80 steps, it also goes back to the sentence that was selected) · go back to the original OCR text of the page.

        How it works

        1. Editable model. The flat page format (words + ranges) is turned into nested lists: paragraphs → sentences → words. Every correction is a small function that changes these lists. Then the model is turned back into the flat format, and clauses are recalculated with the same rules as the build (segment.js). Converting all 472 pages to the model and back gives exactly the build's files — this was checked.
        2. Keeping the boxes. When a sentence's text changes, the new words are matched to the old words (longest common subsequence). Unchanged words keep their box. A changed word takes the box of the word it replaces; a split word (“Doyou” → “Do you”) shares the old box by character length; joined words get the union of the boxes. New words have no box.
        3. Staying on the same sentence. The app remembers the sentence you are on (being read, last read, clicked or corrected — currentFocus). Correction mode opens with it selected and centred; Done goes back to reading with the same sentence highlighted and centred (setFocus).
        4. Drag and drop. Built with pointer events rather than the browser's HTML drag and drop (which in testing sometimes ended without a drop), so it works the same with a mouse, pen or finger. Only the handle starts a drag (so text can still be selected), after the pointer moves 5 px; Esc cancels. While dragging, dropTarget finds the gap under the pointer; in the gap between two paragraphs, the upper half means “end of the paragraph above” and the lower half “start of the paragraph below”. The drop runs the moveTo correction, so Undo works as usual.
        5. Saving. After each change the whole page is sent to the server (PUT /api/text/…) 0.4 s later. Saves of the same page run one at a time, so the newest version always wins. The server checks the data and writes web\edits\<book>\<page>.json. Pages without corrections still come from web\data\text.

        6.18 My audio: MP3s with a natural voice

        Any paragraphs or sentences of a page can be turned into one MP3 read by a Microsoft Natural voice. An icon next to the paragraph plays it, the text is highlighted sentence by sentence and word by word while it plays, and the My audio tab keeps all of them (play, download, rename, delete, filter, search).

        How it works

        1. Why the server makes the MP3. The browser's speech engine can only speak; it cannot save what it says. So the local server (web/tts.py) uses edge-tts, a Python package that talks to the same online Natural voices Microsoft Edge uses for Read Aloud. Creating needs the internet; the MP3 then plays offline. (edge-tts uses Edge's service without an official licence for other apps, so Microsoft could change it — the official alternative is Azure Speech with a key.)
        2. Pieces of up to 10 sentences. The chosen sentences are spoken in pieces of up to 10 (four requests at a time), so they flow like normal reading. The voice reports the time of every word (WordBoundary).
        3. Cutting and joining. ffmpeg decodes each piece to raw sound. From the word times, each sentence's part is cut out with 0.25 s of silence on each side — the voice itself pauses about 0.85 s at every full stop, so this gives an even 0.5 s between sentences (measured: every cut falls in silence). The chosen pause is added between sentences, and ffmpeg encodes one 64 kbit/s MP3 (with the title as MP3 tag). A file <id>.json next to it keeps the title, voice and the start/end of every sentence and word.
        4. Matching words. The words the voice reports (“page”, “104”) are matched to the page words (“p.104”); words it does not report get times shared out by length (_word_times).
        5. Clicking a sentence plays the MP3 first. Before reading a clicked sentence with the live voice, the app looks for an MP3 of this page that contains it (locate: the one in the player first, then the newest). If there is one, the MP3 plays from that sentence — no internet needed; clicking the same sentence pauses, another one jumps. Clause mode starts at the clause's first word, word mode plays just that word. Only sentences without an MP3 use the live voice, and without internet the live voice switches to an offline Windows voice at once.
        6. Subtitles. Every MP3 gets <id>.srt and <id>.vtt with the time of each sentence (made from the JSON timing, also for MP3s made earlier); CC in the list downloads the .srt.
        7. Playing. The normal audio player plays the MP3. Every frame it reports the time; the app finds the sentence and word at that time and highlights them on the page and in the text (follow). If the text was corrected after the MP3 was made, each sentence is found again by its text.

        6.19 Translation

        Every sentence can be shown with its translation in one of 43 languages (Arabic, Persian, Turkish, Spanish, Chinese…). The language is chosen in the Translation tab of the settings (sliders button). The translation is shown in two places, each with its own on/off button: under each sentence in the Text list (the translate button in the Text tab, or L) and in a popup on the page (the translate button at the top).

        WhereWhat you get
        Text tabThe translation under every sentence; paragraphs are kept
        On the pagePoint at a sentence (or clause): its translation in a box under the line. In Word mode the box also shows “word → translation”.
        While readingThe translation of the sentence being read is highlighted and kept in view
        Copy / SaveEach sentence's translation is written after it
        Whole bookTranslate the whole book now goes through every page (can be stopped and continued), so everything works offline

        How it works

        1. Which translator. The local server (web/translate.py) uses Google's free translators — no account or key. First the address Chrome uses for “Translate this page” (translate-pa.googleapis.com/v1/translateHtml); if it fails, the older address (translate.googleapis.com/translate_a/single?client=gtx). Microsoft's free address, the first idea, no longer answers (404). These are not official APIs for other apps, so they could change one day; the official alternative is the Google Cloud or Azure Translator API with a key.
        2. Whole paragraphs, but every sentence comes back on its own. A sentence translated alone loses its context (“he”, “it”, tenses). So each paragraph is sent as one piece with its sentences marked: <a i=0>First sentence.</a> <a i=1>Second one.</a>. Google translates the paragraph as a whole and keeps the marks, so each sentence's translation is found by its number. A normal page is one request (about 1 s). If Google ever moves a sentence into another one, those sentences are sent again one by one.
        3. The backup address. It answers in pieces [translation, original]. The originals, put together, are exactly the text sent, so each piece's position shows which sentence it belongs to (_align).
        4. Not too fast. Google blocks a computer for a while when it gets many requests in a row (it then sends every request to its “unusual traffic” page). So requests to the same address are at least 0.4 s apart, Translate the whole book waits 1.5 s after each page that really needed the translator, and an address that answers “too many requests” is left alone for 2 minutes (4, 8… up to 30 if it happens again) instead of being asked again at once. The server tells the page how long to wait (HTTP 429 with wait); the book translation shows a countdown and goes on by itself, and the Text list tries again by itself.
        5. Saved once, offline after. The result is saved in web\translations\<language>\<book>\<page>.json, keyed by the English sentence. Opening the page again reads the file (no internet). A sentence that was corrected is new text, so only its paragraph is sent again. Single words (Word mode) are saved in <language>\words.json.
        6. In the page. translation.js asks for the page's translations once per page version and language, then puts a <span class="tr"> after the last word of each sentence in the Text list, with dir="rtl" for Arabic, Persian, Urdu, Kurdish and Hebrew. The box on the page shows the sentence translation at once and adds the word when it arrives. It is placed under the whole sentence (all its lines), above it if there is no room, else beside it, and it moves with the page when you scroll — so it never covers the sentence you are reading.

        6.20 Phones and tablets

        The same app works on Android and iPhone; below 700 px of width the layout changes (one place in app.css, @media (max-width: 700px)), and touches replace the mouse. Nothing is installed: the phone opens the app's address in its browser, and Add to Home screen gives it an icon and a full screen (manifest.webmanifest, icons from make_icons.py).

        On the computerOn the phone
        Point at a sentence (highlight, translation popup)Tap it: it is read, and its translation shows (a touch screen cannot point)
        ← / → keys, page buttonsSwipe left or right on the page (when the page is not wider than the screen, or at its edge)
        Zoom buttonsPinch with two fingers; near the width of the screen it snaps back to “fit width”

        How it works

        1. Layout. The top bar wraps into two rows (an empty full-width item is the line break); the panel moves from the right column to a second row of the layout grid, so the page simply gets the space above it and “fit width” keeps working. Boxes and dialogs take the whole width; text fields use 16 px so iPhones do not zoom into them; env(safe-area-inset-bottom) keeps clear of the iPhone's home bar.
        2. Touch. touch-action: pan-x pan-y on the page lets the browser scroll but leaves pinching to the app: two fingers on touchmove set the zoom so that the point between the fingers stays put; one quick sideways move turns the page. The page ignores pointermove from fingers (no hover), so a tap is just a click.
        3. Tests. The phone checks run the app at iPhone size with real touch events sent through the browser's DevTools protocol (tap, swipe, two-finger pinch, double tap, dragging the sheet).

        6.21 Login, GitHub and your own website

        As long as the app runs on this computer only (127.0.0.1) it needs no password. As soon as other devices can reach it, it does: Start for phones (home Wi-Fi).bat (server.py --lan, a 6-digit PIN made on first use) or a web host (server.py --proxy, the password in AEF_PASSWORD). Without one, the server refuses to start on the network.

        • Login (auth.py): the right password gives a cookie “valid until time”, signed with HMAC-SHA256 with a key made from the password — nothing is stored on the server, logins survive restarts, and a new password logs everybody out. The cookie is HttpOnly, SameSite=Lax, and Secure behind HTTPS. After 8 wrong tries from one address it waits 15 minutes.
        • Every request goes through gate(): without a login only login.html, the manifest and the icons open; pages are sent to the login page, the API answers 401 (the app then goes to the login page itself). Only /web/ and /.shared/ are served as files, never Python files, tools, tests, saved data or server-config.json.
        • GitHub gets the code only (.gitignore lists what goes in, about 0.6 MB): not the book content (Oxford University Press's, about 1 GB), not your data.
        • The host is a small Ubuntu VPS (not shared hosting: the Python helper must run all the time). deploy/setup-server.sh installs Python and Caddy, which gets the HTTPS certificate by itself and passes every request to the app; the code comes from GitHub with a read-only deploy key; the app runs as a systemd service. deploy/upload-content.ps1 copies the content and your data once; deploy/update.sh takes the newest code later. The steps: deploy/README.md.

        6.22 Lingua Books: the library, accounts, a public website

        The same reader opens any book: a text, a PDF or photos of pages. The home screen is a library with tabs: Public library (books shared with everyone), My books (private until shared), On this computer (only on this computer: the disc's three books) and, for admins of a website, Admin.

        Kind of bookHow its pages are made (library.py, in the background)
        TextSet into pages of 1200 × 1700 px with the Atkinson Hyperlegible font (made for readability). Every word is drawn by the app, so its place is known exactly; paragraphs, headings (#) and line breaks are kept; a picture can go under the title.
        PDFEach page is drawn with pypdfium2 (1600 px wide); its words and their places come from the PDF itself with pdfplumber, grouped into lines. A page without text (a scan) is read with OCR.
        PhotosTurned upright (EXIF), made at most 2000 px wide, read with OCR (ocr.py: Tesseract on the Linux server, the OCR built into Windows on this computer).

        Then the same steps as for the disc (segment_text.py: lines → paragraphs → sentences → clauses) give each page its words, sentences, clauses and paragraphs, so everything else — reading aloud, translation, repeat, MP3s, corrections — works the same. Each page keeps its own size (the disc's pages are all 1984 × 2496).

        Accounts and who may do what

        • On this computer (server.py): no login; everything belongs to you, the admin.
        • Home Wi-Fi (--lan): the PIN, then as on this computer.
        • Public website (--public --proxy): anyone reads the public books; adding books, MP3s and corrections need an account. Passwords are kept only as scrypt hashes; the login cookie (30 days) carries the user id, the account's version (raised when the password changes: logged out everywhere) and the end time, signed with the server's secret key. Only the owner (or an admin) changes a book. The disc's books and files are never served.
        • Sharing needs a licence (own work, public domain, Creative Commons…) and a tick “I may share it”. Anyone can report a public book; three reports from different people hide it until an admin looks at it on the Admin page (hide, show again, delete).
        • Limits per account: books, MB, PDF size and pages, photos, books and MP3s per day; sign-ups and logins are limited per address; translations per hour.

        6.23 Following the reading

        While the app reads (or an MP3 plays), the sentence being read stays in the middle of the page and of the Text list — but the person decides: when they scroll, swipe or zoom the page themselves, it stays where they put it, a Back to the reading button appears, and it follows again by itself after the chosen wait. A plain tap on a sentence does not count. Settings → Follow: on/off (also the target button in the reading bar, and F), where on the page (middle, near the top, only when it leaves the screen), the scrolling speed (or jump at once), the wait after scrolling, and whether the Text list follows too.

        1. Who is scrolling? follow.js watches each area (the page, the Text list) separately: a mouse wheel, a finger that moved more than 10 px, two fingers (zooming) — or a scroll right after the person pressed something there (scroll bar, keys) — is the person. Scrolls caused by the layout (the panel getting taller) and by the app's own scrolling do not count.
        2. Its own smooth scrolling (eased, with the chosen duration) instead of the browser's, so the speed can be set and the app knows which scroll events are its own; the person's wheel or finger stops it at once.
        3. Where the middle is: the part of the page that can be seen — above the reading bar, and on phones above the panel at the bottom. A sentence taller than that is shown from its start.

        10. Troubleshooting

        The app says “The book data could not be loaded”

        The page was opened directly as a file. Start it with Start American English File.bat instead (see 6.1).

        The black window says “Python is not installed”

        Install Python 3 from python.org and tick “Add python.exe to PATH”, then start again.

        Nothing is spoken / “This browser cannot read text aloud”

        Use Microsoft Edge or Google Chrome. Check that Windows has voices: Settings → Time & language → Speech. Try the “Test voice” button in the voice settings.

        A “Natural” voice stops working

        These voices need internet. The app switches to an offline Windows voice by itself and shows a message. You can also choose David or Zira in the voice settings.

        An answer key shows “could not be shown”

        Ruffle is missing. Run build_all.ps1 again — it downloads Ruffle into web\vendor\ruffle when it is not there.

        A video does not play

        Check that web\data\video has the MP4 files. Run python web\tools\convert_videos.py again; it only converts missing ones.

        OCR says “English OCR language is not installed”

        Add “English (United States)” in Windows language settings, then run the build again.

        Some text is wrong or a sentence is split badly

        OCR is very good on normal text but can be wrong on small labels on pictures. Splitting rules are in segment_text.py; after a change, run only python web\tools\segment_text.py. You can also correct a word by hand in the page's JSON file in web\data\text.

        Correction mode says “Not saved”

        The app could not reach its server. Check that the black window is still open (or start the app again with the .bat file), then make any small change again — the whole page is saved each time.

        Translation says “The translation failed” or “busy”, or does not appear

        “Busy” means Google got too many requests from this computer in a short time: the app waits the time shown and goes on by itself. Otherwise: the first translation of a page needs the internet. Check the connection and open the page again (or switch translations off and on with L). Pages translated before work offline. If it says the server is an older version, close the black window and start the app again.

        The port is already in use

        The server tries the next 19 ports by itself. The black window shows the address it used.

        11. Known limits

        • OCR text can contain small mistakes, mostly in labels on pictures and maps, and some exercise numbers stick to words.
        • 156 Teacher's Book pages are not on the original disc, so they cannot be shown.
        • Natural voices need Edge and an internet connection; offline voices are more robotic.
        • Ruffle plays the answer keys well; other old Flash parts of the disc (interactive exercises not linked from the pages) were not used.
        • Translations are machine translations (Google Translate): good for understanding, not always perfect. The free addresses are not official APIs and could change, and Google limits how fast they may be used.
        • Python must be installed to run the small server.
        • The rebuilt app is for use on your own computer. The book content belongs to Oxford University Press.
